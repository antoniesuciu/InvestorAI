# Macroeconomic data, revisions, and verification

Research date: **2026-10-27**. Primary documentation review by the coordinating researcher; findings are proposals for review, not authorization to integrate sources. No accounts were created or dependencies installed. Links below were accessed on this date unless an access limitation is stated.

## Recommended direction

Use **BLS and BEA directly for US statistics, ECB for euro-area monetary/FX data, and Eurostat for selected European statistics**. Preserve permissible releases and revisions locally from the start. These are free public statistical services; data availability is series-specific. They do not supply a complete equity price or analyst-consensus dataset.

**Do not assume FRED/ALFRED can serve as this project's durable data warehouse.** Its API has valuable vintage facilities, but the current legal page restricts caching and AI-development use. The older API terms page is materially less restrictive. Treat permission as unresolved for our intended storage and AI workflow; use direct originating agencies for the core stack. This conclusion is a project suitability assessment, not a claim that every use of FRED is prohibited. [Current FRED legal terms](https://fred.stlouisfed.org/legal/), [older API terms](https://fred.stlouisfed.org/docs/api/terms_of_use.html).

## Historical availability without assuming ALFRED permission

- **BEA:** The GDP landing page exposes archived estimates and vintage-history files. Inspect the actual tables, definitions and release dates in Phase 2 before using them in an as-of query. Do not assume all BEA datasets have identical revision archives. [Previously published GDP estimates](https://www.bea.gov/data/gdp/gross-domestic-product).
- **BLS CES:** Its documented vintage tables cover published values since the first preliminary May 2003 estimates, with much earlier reference-month histories for some series. Those are two different time axes. This is a specific historical payrolls resource, not proof of vintage coverage for every BLS series. [CES vintage documentation](https://www.bls.gov/web/empsit/cesvininfo.htm).
- **ECB:** `includeHistory=true` requests prior versions; `updatedAfter` returns changed observations, including additions, revisions and deletions. Neither proves a precise first-publication clock for every series. Validate revision timestamps and supported formats for each dataflow. [ECB API parameters](https://data.ecb.europa.eu/help/api/data).
- **Eurostat:** Start an append-only local snapshot history where permitted; current downloads cannot recover earlier states. A series beginning decades ago does not imply decades of vintage availability. [Eurostat API introduction](https://ec.europa.eu/eurostat/en/web/user-guides/data-browser/api-data-access/api-introduction).
- **Philadelphia Fed RTDSM — supplementary research candidate:** Publishes complete vintage histories and selected first/second/third-release values; its site says monthly updates and permits informational/educational/research use. Check variable notes, the original owners' rights, and scope before use beyond research. Public download links need no paid account, but this review did not test workbook completeness or establish an unrestricted commercial license. [Dataset](https://www.philadelphiafed.org/surveys-and-data/real-time-data-research/real-time-data-set-for-macroeconomists), [history index](https://www.philadelphiafed.org/surveys-and-data/real-time-data-research/real-time-data-set-full-time-series-history), [site terms](https://www.philadelphiafed.org/about-us/privacy-notice).

## FRED legal/documentation discrepancy

The full legal page incorporates API, account, series and MCP conditions. Its current API restrictions materially change the suitability implied by older documentation. The connector is designed for AI-host interactions, but its separate section retains a caching prohibition and is not an authorization for our warehouse. Seek explicit no-cost clarification if later work depends on these facilities. Do not route data through MCP to evade API conditions. [Full current terms, API and MCP sections](https://fred.stlouisfed.org/legal/).

FRED's v1 technical documentation describes `realtime_start`, `realtime_end`, `vintage_dates`, and an initial-release output mode. These solve a technical version-selection problem only where historical vintages exist. They do not resolve licensing or exact within-day release availability. [Real-time periods](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html), [vintage dates](https://fred.stlouisfed.org/docs/api/fred/series_vintagedates.html), [observations](https://fred.stlouisfed.org/docs/api/fred/series_observations.html).

## Financial interpretation requirements

For every series, record source, dataset/series identifier, units, frequency, seasonal adjustment, observation period, publication time/precision, vintage, revision status, retrieval time and license. Keep source levels distinct from transformations. A quarterly level at a seasonally adjusted annual rate is not a quarterly growth rate. Year-over-year change, quarter-over-quarter change, and annualized quarter-over-quarter growth require different formulas and validation. Economic-period dates must never be treated as public-release dates.

Match agency release calendars and local time zones, including daylight saving time, before applying publication-time filters. Where only a release date is known, use a conservative documented availability rule or exclude intraday analysis. Maintain a separate latest-data research view and a historically available view; make their differences visible.

## Phase 2 macro acceptance checks

1. Confirm source-specific access, storage, analysis and attribution rights for the exact series and intended use; use public non-billing endpoints or documented free keys only.
2. Compare a narrow sample of BLS/BEA values against their own published releases. Match vintage, units, seasonal adjustment and rounding before diagnosing a mismatch.
3. Retrieve one historical revised observation and its earlier release from an agency archive; prove an as-of query excludes the later revision.
4. Demonstrate ECB history/delta semantics on one dataflow; apply deletions as versioned changes rather than overwriting or dropping evidence.
5. Check Eurostat schema/category changes and preserve permitted snapshots prospectively, with explicit absence of historical vintages.
6. Tie freshness alerts to release schedules and expected publication delays, not merely HTTP success or the last observation's period.

These are proposed implementation checks. No Phase 2 ingestion, storage setup, model development, or numerical strategy evaluation was performed here.
